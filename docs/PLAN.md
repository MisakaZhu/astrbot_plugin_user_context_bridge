## 验收矩阵 A01-A18

见 docs/ACCEPTANCE.md（P6 建立完整映射）。要点：所有场景用合成数据，断言最终模型请求、实际持久化与回复目标，不只断言 helper 返回值；真实 QQ 验证单列待用户执行。

## 硬约束（摘自主计划，实现必须遵守）

1. 共享身份 = 平台实例 + 机器人 self_id + 人格范围 + 真实 sender_id；不同用户/机器人/人格隔离；默认人格有稳定值。
2. 首次启用必须显式配置范围；范围内群 A、群 B、私聊双向连续；范围外不采集不注入；个人开关不能扩大管理员授权。
3. 完整闭环：读取、模型运行、真正持久化；唯一权威历史来源；无双写/回灌。
4. 不把全群 UMO 历史当归个人历史；排除他人轮次、未唤醒闲聊、机器人自言、管理命令。
5. 保留当前人格、系统规则、工具结构与其他插件动态内容；不保存隐藏思考；临时提示词不反复持久化。
6. 同身份并发有确定顺序；异常/取消/卸载不卡锁；完成钩子不当作写回完成。
7. /uctx 管理命令 + 原生 /new、/reset 语义明确；epoch 防旧请求复活旧历史；停用/卸载不静默回灌。
8. 不改 AstrBot 核心、不全局 monkey patch、不动其他插件与云端。
9. 首先支持 aiocqhttp（QQ OneBot）+ 内置 Agent；4.26.0/4.28.0 以真实宿主集成证据为准。
