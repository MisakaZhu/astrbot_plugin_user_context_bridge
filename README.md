# astrbot_plugin_user_context_bridge

同一 QQ 用户在**同一机器人**及**明确启用**的群聊与私聊之间，共享连续的真实对话历史：在群 A 问过的问题，到群 B 或私聊里可以接着聊——近期用户消息与机器人回复真实衔接，不是长期记忆、人物画像或摘要注入。

0.7.0 起共享范围可选（`history_scope`）：

- **persona（默认，兼容旧版）**：按当时人格隔离——同一用户在不同人格下的历史互不相通；
- **user（跨人格共享）**：同一用户跨人格共享同一份历史，但每个窗口仍使用该窗口当前人格、系统规则与工具（黑白人格轮换、群/私聊不同人格时也能接续）。

模式切换由插件**持久化的生效模式**识别（真实 reload/重启均生效）：显式切换从新代次开始（旧记录归档可查）；仅改配置后 reload 相同值、重启或人格黑白轮换不清空。退出状态跨模式继承：persona 退出切到 user 仍退出；user 退出保护该账号现有人格与未来新人格，单人格 `/uctx on` 只解除该人格。

> 状态：0.7.0 候选（本地开发与合成测试完成，待独立验收与实机验证）。默认关闭，安装后需管理员显式启用并配置范围。

## 支持边界（v1）

- 适配器：QQ OneBot v11（aiocqhttp）。
- Agent 路径：AstrBot 内置 Agent（普通对话流程）。
- 宿主版本：4.26.0、4.28.0（本地实测；其他版本未验证不宣称）。
- 不支持：QQ 官方适配器、Dify/Coze 等第三方会话执行器、WebChat 专用行为。

## 工作方式（摘要）

1. **共享身份**：平台实例 + 机器人 self_id + 共享范围 + 真实发送者 QQ 号。不同用户、不同机器人天然隔离；persona 模式下不同人格继续隔离，user 模式下同一用户跨人格共享。无论哪种模式，**每个窗口的当前人格、系统规则、开场白与工具都按宿主真实规则生效**，历史里只带对话内容，不带旧人格的系统提示。
2. **读取**：范围内每轮请求，在宿主构建 LLM 请求后（`on_llm_request`）把本轮上下文替换为「人格开场白 + 该身份当前代次的共享历史」，同时短路宿主对原窗口的整段写回（`req.conversation = None`，宿主 `_save_to_history` 以此提前返回，无双写/回灌）。
3. **写回**：插件自身 SQLite 轮次账本是唯一权威历史源。成功轮次保存完整 user/assistant 配对与工具调用轨迹，并记录实际人格（`source_persona`）；失败、中止、中断分别记录状态，不产生伪成功。
4. **并发**：同身份跨窗口请求按轮次序号确定顺序；不同身份互不阻塞。SQLite 事务与唯一约束覆盖多连接；同库双实例以启动租约检测并拒绝并发写。
5. **清空**：`/uctx reset` 切换 epoch——persona 模式只清当前人格的历史，user 模式清该用户跨人格的整份有效历史；清空前的慢请求不会把旧历史写回。
6. **路由不变**：`unified_msg_origin` 与回复目标永不修改，回复仍发回触发窗口；其他插件的人格、系统规则、工具配置正常生效。
7. **模式切换从新历史开始**：显式切换 persona↔user 会开启新代次（旧记录归档保留可查，不自动合并）；仅改配置后 reload、重启或正常人格轮换**不会**清空。

详细架构决策见 [docs/ADR.md](docs/ADR.md)。

## 配置（默认关闭）

安装后默认不采集、不共享。管理员在配置中显式启用并指定允许的来源范围（群号列表 + 是否含该用户私聊）。配置模板见 `_conf_schema.json`：

| 配置 | 说明 |
| --- | --- |
| `enabled` | 总开关（默认 false） |
| `shared_groups` | 参与共享的群号白名单 |
| `include_private` | 允许私聊参与共享（对范围内符合条件且未退出的用户生效，并非选择某一个 QQ 号） |
| `history_scope` | `persona`（默认，按人格隔离）/ `user`（跨人格共享）；**切换会从新历史开始，旧记录保留供查询** |
| `max_history_turns` | 每次注入的最大历史轮数（默认 40，0 不限） |

个人命令 `/uctx`：

| 命令 | 说明 |
| --- | --- |
| `/uctx status` | 查看自己的共享状态与当前模式（不显示他人标识与聊天正文） |
| `/uctx off` | 退出共享：persona 模式退当前人格，user 模式退跨人格整份共享 |
| `/uctx on` | 重新加入（不会自动导入停用期间的原生会话） |
| `/uctx reset` | 清空自己的共享历史（persona=当前人格；user=跨人格整份；epoch 切换，旧慢请求不回写） |

管理命令（管理员）用于维护共享范围；个人 on 不能扩大管理员允许范围。个人退出状态在升级与模式切换时继承（persona 退出切到 user 仍退出；user 退出保护该用户全部人格，直到主动 on）。

## 本地记录查看与导出（0.7.0 新增）

插件的共享历史保存在本机（运行 AstrBot 的电脑/服务器）插件数据目录下的 `uctx_ledger.db`。随安装包提供只读命令行工具 `tools/uctx_records.py`（纯 Python 标准库，不启动 AstrBot、不需要 QQ/模型凭据/网络）：

```bash
# 数据库路径（AstrBot 数据目录下）：
#   data/plugin_data/astrbot_plugin_user_context_bridge/uctx_ledger.db

# 1) 列出身份分区（仅元数据，不含聊天正文）
python tools/uctx_records.py list --db data/plugin_data/astrbot_plugin_user_context_bridge/uctx_ledger.db

# 2) 导出 JSON（程序可读；筛选：平台/机器人/用户/来源/人格/时间/状态/归档）
python tools/uctx_records.py export-json --db .../uctx_ledger.db \
    --platform aiocqhttp --sender 123456 \
    --from 2026-09-01T00:00:00 --to 2026-10-01T00:00:00 --out export.json

# 3) 导出 HTML（自包含离线页面，浏览器直接打开，可站内搜索）
python tools/uctx_records.py export-html --db .../uctx_ledger.db \
    --sender 123456 --out export.html
```

约定：

- 默认只导出**当前代次**的 completed 轮次；归档（reset/切模式前）与 failed/aborted/interrupted 需显式 `--archives` / `--status` / `--all-statuses`，并在结果中标注状态。
- 时间为本地时区 ISO8601（无偏移按本地时间解释），起点包含、终点不包含；默认上限 500 条，截断会明确标注。
- 页面是导出时点的静态快照（不实时刷新）；聊天内容已按不可信文本转义，无外部资源；输出文件默认写到库目录 `exports/`，绝不覆盖源数据库。
- 0.6.0 旧库需先由新版插件启动一次完成自动迁移（迁移前自动备份）；本工具不自行升级旧库。
- Windows / Linux / 容器挂载数据目录均适用：`--db` 指向挂载后的实际 `.db` 文件即可。

## 原生命令语义（成功关联联动）

- 原生 `/reset`、`/new` **在宿主实际执行成功时**同步切换发送者的共享历史 epoch（仅影响本人）：插件不注册同名命令、不拦截宿主行为，而是在宿主 builtin 命令成功完成后（结构化激活证据 + 宿主本地成功标记 `_clean_group_context_session`）触发联动并独立提示；同一命令成功只应用一次。
- 宿主拒绝（无可用模型/权限不足/命令被禁用/改名后旧名/自定义过滤拒绝）时**不联动**——共享历史不被误清；改名后的新名称成功时正常联动。
- 未共享用户使用原生命令：插件不动作、不加提示，宿主行为完全不变。
- 等效命令 `/uctx reset` 仍可用（本人维度清空，无需窗口权限）。

## 停用 / 卸载 / 回滚

- 停用：范围内会话恢复宿主原生会话行为；插件不再读取或写入共享历史；历史不会静默回灌原生会话。
- 卸载：恢复宿主原路由；插件数据保留在插件数据目录，可人工清理，不自动销毁。
- 回滚：直接停用或卸载插件即可（插件不修改 AstrBot 源码与宿主数据库结构）。

## 隐私与数据

- 对话正文仅存于本地插件数据目录（SQLite）；日志默认不输出对话原文。
